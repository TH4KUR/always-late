# Functional Validation Across Precision: Implementation Plan

> **For the agent executing this (a 40-minute recurring job, one bounded step per firing, or a chat):** use `superpowers:executing-plans` and `superpowers:test-driven-development`. Checkboxes record work; a ticked box needs the evidence written in [`STATUS.md`](../../../reports/functional_validation/STATUS.md). This plan authorises no parallel agents except one-off literature checks.

**Goal:** answer F1 to F4 and B of the [design](../specs/2026-10-21-functional-validation-design.md): does removing a language's selective SAE feature group harm that language beyond activity-matched controls, is that kept in each quantized model, where does quantization damage sit, and does association retention predict functional retention.

**Architecture:** one new GPU runner that, per precision, runs the 13 lower blocks once per batch (cached) and then re-runs only the upper blocks for each edit configuration, with edits that preserve the SAE error term; item-level results are saved and analysed on the CPU by a separate module (paired cluster bootstrap), then turned into tables and figures. The D-035 collector, `phase1_run.py` and every historical output stay untouched.

**Tech stack:** the existing environment on Ada (torch 2.14, transformer-lens 3.9.0, sae-lens 6.54.5, matplotlib 3.10 on Ada; local venv `~/.venvs/anlp-torch` has torch/numpy/scipy, matplotlib to be installed), unittest, `scripts/g0/mutcheck.py`, the existing sbatch pattern and artifact tooling.

## Task 1: task layer `scripts/g0/phase1_func_tasks.py` (+ `tests/test_phase1_func_tasks.py`, stdlib; tokenizer injected)

**Interfaces.** `load_belebele(root, code) -> list[dict]` (validates 900 items, the four options, `correct_answer_num` in 1..4); `passage_origin(items, flores_dev_lines, flores_devtest_lines) -> {passage_key: "dev"|"devtest"|"mixed"|"none"}` and `split_items(items, origin) -> {"cal": [...], "eval": [...], "excluded": [...]}` (calibration = dev-origin passages, evaluation = devtest-origin, mixed/none excluded and counted; the same passage keys in every language, so the split is language-independent); (`passage_origin` classifies each passage by exact sentence match against the FLORES dev and devtest lines after whitespace normalisation); `format_prompt(item, fmt)` for `letter` and `cloze`; `encode_mc(tokenize, item, fmt) -> {tokens, cand_ids/option_spans}` (BOS handling as the regime, no special tokens inside); `lm_ids(n_total, n_pilot, n_eval, seed) -> {"pilot": [...], "eval": [...], "reserve": [...]}` (disjoint, seeded, identical for all languages).
**Tests first.** split is deterministic, disjoint, language-independent; origin on planted passages (dev only, devtest only, straddling, absent); prompts contain exactly the four options in order and never the answer key; candidate token ids are four distinct ids; `lm_ids` disjoint and sorted; refuses malformed items.
**Mutants.** swapped option order, answer-number off by one, split depends on language, a mixed passage allowed in evaluation, origin ignoring whitespace normalisation.

## Task 2: intervention library `scripts/g0/phase1_func_intervene.py` (+ `tests_torch/test_phase1_func_intervene.py`)

**Interfaces.** `apply_edit(...)`: `x' = x + (a_new - a[:, idx]) @ W_dec[idx]` in float32 with kinds `ablate`, `scale(alpha)`, `resample(pool, generator)` (whole group vectors of random pool rows), `mean(mean_vals)`, `donor(a_donor)`, `sham`; `apply_edit(resid [B, L, d], valid [B, L], encode, W_dec, idx, kind, **kw) -> (resid', stats)` that edits valid positions only (never BOS, never padding), returns the input dtype, and `stats` = mean `||Delta x|| / ||x||` over edited positions and mean number of active group features. A toy SAE (random decoder, JumpReLU thresholds) in the tests.
**Tests first.** identity (`a' = a`) returns `x` exactly; ablating all features leaves exactly `x - (x_hat - b_dec)` (the error term preserved); the change is confined to the decoder span of the group; edits at invalid positions are zero; BOS and padding rows bit-identical; `scale(1)` is identity and `scale(0)` equals `ablate`; `resample` draws rows of the pool only and is seeded; `donor` with `a_donor = a` is identity and with the other model's activations moves the residual by exactly `(a_donor - a) @ W_dec[idx]`; sham numerically near zero in bf16; norm statistic correct on a hand case.
**Mutants.** error term dropped (decode-and-replace instead of delta), BOS not excluded, alpha applied to the wrong side, pool index off by one, wrong decoder rows, float32 cast removed, edits applied to padding.

## Task 3: groups and controls `scripts/g0/phase1_func_groups.py` (+ `tests_torch/test_phase1_func_groups.py`; generated `reports/functional_validation/groups_manifest.json` and `groups_matching.md`)

**Interfaces.** `dev_view` (keeps only the dev fields), `group_members(sel, l)` (selective features with dev peak l ranked by dev mean activation on l, ties by id), `top_k(members, K)` (nested prefixes), `pool_ids(sel)` (`supported & ~selective`), `draw_controls(sel, l, group, R, seed, M=3)` (greedy nearest-neighbour matching, one pool feature per member without replacement, from the most active member down, uniformly among the M nearest available, L1 on log mean activation and log rate of language l, returns `sets` and the mean `gap`), `build_manifest(selectivity_path, Ks=(16, 64, None), Rs=(5, 5, 3), seed)`, `verify_manifest`, `matching_table`, CLI `build|verify|report`.
**Tests first.** nested groups; sizes; controls disjoint from every selective feature, from the pool only, equal in size, without replacement within a draw; hand-built cases for the nearest choice (including the rate term), for the greedy order and for a pool exactly as large as the group; draws differ across seeds and are reproducible; a language's controls depend on its own statistics only; matching quality on a pool with enough candidates; pool smaller than the group is an error; manifest round trip, tamper and source-hash detection; dev-only fields (an extra field is dropped, a missing one is an error).
**Mutants (19, all killed).** rank ascending, ties by descending id, another language's statistics, pool including selective features, same seed for all draws, rate or activation term dropped, matching in id order, pool feature reused, M ignored or not clipped, signed gap, M check removed, small pool tolerated, top-K off by one, source hash or rebuild comparison removed, extra fields kept.
**Output check against the real cohort (done 2026-10-21).** Group sizes 73 (por_Latn) to 1,719 (eng_Latn); the manifest equals a fresh rebuild; matching in [`groups_matching.md`](../../../reports/functional_validation/groups_matching.md): 75 of 81 cases within [0.8, 1.25], exceptions listed in the design (section 4); the first cell-based draft was replaced before any outcome existed.

## Task 4: runner `scripts/g0/phase1_func_run.py` + `run_functional.sbatch` (+ `tests_torch/test_phase1_func_run.py`)

**Interfaces (injected callables as in `run_survival`).** `lower(tokens) -> resid`, `upper(resid_edited) -> final hidden`, `nll_from_hidden(hidden, tokens, valid) -> per-sentence (sum NLL, count)` (chunked unembedding with the final norm and logit soft cap, no whole-vocabulary tensor), `mc_scores(...)`, `encode`, `W_dec`; configuration list built from the groups manifest; `run_precision(bits, tasks, configs)` restores, quantizes, caches `a` for the baseline, runs every configuration, returns item-level arrays keyed by (task, language, config); `run_rescue` (FP pass first, FP features cached sparsely, then the recipient); fidelity quantities (B) from the baseline pass; output `.pt`/`.json` with provenance (commit, versions, hashes, seeds).
**Gates inside the runner (each fails loudly).** (1) cached lower half + upper half equals the full forward bit for bit on unedited input; (2) identity edit equals baseline bit for bit; (3) sham within a stated tolerance; (4) the encoder run on the cached residual reproduces `a` from the full path; (5) the first run records the measured tokens per second and peak memory.
**Tests first** with a toy causal model (cumulative-mean mixing layers, tiny vocabulary) and a toy SAE: gates pass on the toy; an injected bug in each gate path fails the matching gate; item arrays have the right shapes; paired items identical across configurations; the rescue patch with FP = recipient returns the baseline; the all-features and error-term bounds add up to the full-residual patch on the toy; output-language mass computed from a hand vocabulary.
**Mutants.** upper half started at the wrong layer, edit applied before instead of after the hook, BOS edited, rescue donor from the recipient, controls reusing the group ids, soft cap removed, wrong target shift.

## Task 6: analysis `scripts/g0/phase1_func_analysis.py` (+ `tests_torch/test_phase1_func_analysis.py`)

Paired cluster bootstrap (clusters = sentence ids across languages, or passages), harm, `E_l^b`, `rho`, classification, rescue fractions, decomposition, F4 subgroup contrasts, per-condition perturbation-norm tables, SAE-fidelity table (B), coverage table; report generator `reports/functional_validation/results/<task>/report.md`, `analysis.json`, CSV tables.
**Tests first** with planted item-level data: a planted effect is recovered, a planted null gives an interval around 0, bootstrap resamples whole clusters (an id appears in all languages or none), the same resamples are used across precisions (a paired difference of identical data is exactly 0 with zero width), ratio classification on planted attenuation/amplification/preservation, rescue fraction on a hand case, negative harm is kept, deterministic under the seed.
**Mutants.** items resampled independently of clusters, different draws per precision, sign flip of harm, ratio inverted, controls averaged over the wrong axis, denominators not fixed.

**Task 6b (DONE 2026-10-22: 32 tests, 30 mutants killed): T-MC analysis `scripts/g0/phase1_func_mc_analysis.py` (+ `tests_torch/test_phase1_func_mc_analysis.py`), written 2026-10-22 before the code; T-MC is the only confirmatory family of the design (section 6), so this module is on the critical path of any confirmatory claim.** Item score: four option scores per item (letter format: log-probabilities of the four option letters at the final position, `cand_logp`; cloze format: length-normalised option log-likelihood, `-nll/ntok` of the four rows of the item); `log p_correct = log_softmax(scores)[answer]` (the four-way probability of the correct option, design section 6; computed with a stable softmax); harm of an edit on an item `h_i = -(log p_correct(edit) - log p_correct(none))`, same precision, same item; `E_l = mean_i [h_i(zero_K) - mean_r h_i(ctrl_r,K)]`. Uncertainty: paired cluster bootstrap with the PASSAGE (the link of the item key, parallel across languages) as the cluster: B draws of the global passage list with replacement as multinomial counts `W` (B x P), the same `W` for every language and every precision, language effect of a draw = `(W @ S) / (W @ n)` with `S` the per-passage sums of the item values and `n` the per-passage item counts (items dropped as too long simply lower `n`). Everything after the effects reuses the T-LM functions (`macro`, `retention`, `retention_macro`, bands, D-041) so that the outputs have the same schema as the T-LM analysis (`analysis.json`, `effects_by_language.csv`, `retention.csv`, `report.md`) and the figures module reads them unchanged; plus an accuracy table (derived accuracy under none, zero, control mean, sham per language and precision) because accuracy is what a reader will ask for. Covered languages come from the calibration record (`--covered`); item keys must be identical across precisions (error otherwise). **Tests first** with planted item scores: the four-way log-probability (uniform scores give log 1/4, a dominant correct option gives about 0, huge negative scores do not overflow), the cloze rows are scored per item with length normalisation, a planted drop in the correct option gives positive harm and E, a planted null gives an interval around 0, the point equals the mean harm difference by hand, draws resample whole passages (the same passage is in or out for every language), identical data in two precisions give a retention ratio of exactly 1, the sham harm is exactly 0, accuracy is derived from the same scores. **Interval level (DONE 2026-10-22: 8 tests, 17 mutants killed; added from the T-MC freeze, Q19 default a): `retention`, `retention_macro` and `analyse_mc` take a `level` (default 0.95, so the loss analysis is unchanged); statements S1 to S5 use 0.99 (Bonferroni over five). The level changes only the interval and the class of the retention ratios; the D-041 rule that a language needs a clearly positive full-precision effect keeps its fixed 95 % interval, so a stricter level never silently changes which languages are in the macro; the macro effect E of statement S0 keeps 95 %.** Tests: the interval at 0.99 contains the one at 0.95 with the same point; a band edge placed between the two moves the class from preserved to inconclusive; a language whose full-precision lower bound is above 0 at 95 % but not at 99 % stays defined at 0.99; the level is recorded in the output and named in the report. Mutants: the level ignored, the definedness rule moved to the new level, the level applied to S0.
**Mutants.** log-softmax over the wrong axis, harm sign flipped, harm normalised by the wrong count, controls summed instead of averaged, draws different per language, items resampled instead of passages, ratio inverted, keys not checked, accuracy computed from the edited scores of another config.

- **Task 7c (STEP 1 DONE 2026-10-22: the matched subsets, 23 tests, 25 mutants killed, manifests and matching report committed in `reports/functional_validation/f4/`; the GPU jobs and their analysis are step 2): F4, association versus function at equal native activity (design written 2026-10-22 before any code or number; A1 showed that rank is confounded with activity, so the comparison must be matched).** Question (design F4, two-sided): are the features whose language association was LOST at precision b (D-035 status) less functionally important at b than the features that RETAINED it, at equal activity in the quantized model? **Hypothesis written before looking (H-F4, two-sided, exploratory because the statuses were measured on devtest): E_b = harm(zero-ablating the lost subset) - harm(zero-ablating the matched retained subsets) differs from 0 on the language's own text at precision b; "association predicts function" predicts E_b < 0; a null or a positive E_b is a reportable outcome (Borobia et al., P31, found that survival does not predict importance under pruning).** Population: the selective features of the frozen cohort that were established in full precision (`fp_status == retained`, 6,663 features), lost at b = `status != retained`, retained at b = `status == retained`, per language (INT6: 356 lost, 20 languages with at least 8; INT5: 726, 24 languages; INT4: 1,945, all 27). Matching on the NATIVE activity at b from the same status file: x1 = log10(target_rate at b), x2 = log10(target_mean at b), standardised by the pooled SD of the established features of the language and precision; greedy nearest neighbour without replacement (lost features in decreasing activity order), Euclidean caliper 0.25 SD; a lost feature that is inactive at b (rate 0) has no activity-matched partner and is excluded and COUNTED (zero-ablating a feature that never fires is a no-op, which is why the matching is on native activity). The lost subset is capped at 64 per language by a seeded hash order of the feature ids (never by an outcome); R = 3 retained draws, disjoint from each other and from the lost features, each of exactly the same size, a draw that cannot match every lost feature is dropped; a language with fewer than 8 matched pairs is excluded at that precision (reported). Balance: standardised mean differences of x1 and x2 between the lost subset and each draw, per language and pooled (reported; they must be small for the contrast to be read). **Implementation with NO change to any frozen file:** the manifest has the SAME schema as `groups_manifest.json` (the lost subset in `groups[code]["all"]` and under the label K64, the retained draws as the K64 controls, plus an `f4` block with the exclusions and the balance), one file per precision (`reports/functional_validation/f4/f4_manifest_INT<b>.json`); the unchanged runner is called with `--manifest <f4 manifest> --languages <included> --preset floor --precisions FP <b> --split eval --panel` (the `floor` preset is zero K64, three K64 controls and sham), and the unchanged analysis then computes E = harm(group) - mean harm(controls), i.e. exactly the F4 contrast, at FP (the same subsets in the full-precision model: does the difference pre-exist?) and at b (native). Cost: 5 configurations per language, about a quarter of an `eval` precision. Exploratory and labelled; no claim about causation of the association loss. **Tests first** (planted statuses with known rates and means): nearest neighbour and no replacement, the caliper, the standardisation, inactive lost features excluded and counted, the established filter, disjoint draws, the cap by hash and its determinism, the exclusion of small languages, the manifest schema as the runner reads it (checked through `build_configs`), the balance diagnostic. **Mutants.** matching on the wrong precision, replacement allowed, no caliper, unstandardised distance, non-established features in the pools, draws overlapping, cap by outcome or by id order, inactive features matched.

- **Task 7c, step 2a (DONE 2026-10-22: 11 tests, 15 mutants killed): the F4 analysis `scripts/g0/phase1_func_f4_analysis.py` (+ `tests_torch/test_phase1_func_f4_analysis.py`; written 2026-10-22 before the code).** The F4 jobs write the same item files as the loss task (the lost subset sits in the group slot, the matched retained draws in the control slots), but the loss analysis would describe them wrongly (its report says that the selective group matters more than controls and it computes retention ratios, which are meaningless here).
