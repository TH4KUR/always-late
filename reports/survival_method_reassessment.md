## 2. Why the current measurement is insufficient for a stronger claim

The current pipeline identifies language-selective features once, on unquantized dev inputs, and uses a fixed SAE to measure activation correlation before/after quantization on devtest. The feature table reads correlation at the feature's original peak language. Code anchors: [tagging and quantization passes](../scripts/g0/phase1_run.py), functions `run_tagging`, `selectivity_report` and `run_survival`; [feature table](../scripts/g0/phase1_analysis.py), function `feature_table`.

The implemented endpoints are preservation of activation patterns for features selected before compression, not a demonstrated preservation of their language identity or causal role. Illustrative counterexample: a feature keeps the same Hindi responses after quantization but begins responding strongly in English as well. Correlation within Hindi can remain perfect while Hindi specificity disappears. Pearson correlation is also insensitive to a positive rescaling or constant offset, so high correlation does not establish unchanged response magnitude or firing frequency.

Keeping a preselected cohort and a fixed measurement basis is useful; it avoids changing the evaluated population after seeing the intervention. The necessary correction is to call the group **features identified as language-selective before quantization**, and test rather than assume its post-quantization properties. Conversely, a weak response in a frozen SAE can reflect a less suitable measurement basis, not necessarily loss of the represented capability.

## 5. Artifact limitation found during planning

The accumulator's response statistics refer to the unquantized side: [`LangPearson.update` and `_finish`](../scripts/g0/phase1_lib.py) compute firing count and maximum from reference `x`, and export mean activation from `sx`, not quantized `y`/`sy`. Thus the firing/magnitude arrays returned for a quantized rung by `_pack` are not that rung's quantized response profile. `save_outputs` in `phase1_run.py` persists these arrays to `survival.pt` **only for FP**; it saves per-language correlations and loss sums for each quantized rung. `selectivity.pt` holds the original tagging report. Quantized activations and running sums exist during the pass, but the committed schema does not export the post-quantization language-response statistics needed for a full M1 reassessment. Search other cached artifacts before proposing a new pass; do not relabel reference arrays as quantized responses or assume that correlations recover the missing profiles. No claim is made yet about the completeness of every remote or cached artifact.

[Claude's acknowledgment and bounded artifact inventory](../communication/replies/2026-10-21-claude-to-codex.md) confirms these reference-side statistics. The saved correlations cover every language, so the original-peak restriction is an analysis choice, not a missing-correlation problem. FP tagging also saves Deng's nu, which permits a CPU comparison against our S(f) cohort without new activations. Quantized firing counts/maxima are not accumulated; quantized sums/variances exist transiently but are not saved. Claude reports the same schema in the inspected Ada output directory; this is not a comprehensive search of all caches.

Both current FLORES dev and devtest splits have already contributed to the analysis. Reusing them can support transparent exploratory method development, but does not supply genuinely unseen confirmation. Claude reports that the inspected official archive contains only these two splits; independently check corpus availability and overlap before selecting any fresh confirmation data. No new corpus is selected here.

The full support/bootstrap/null procedure also needs sentence-level information, not only aggregated rates. A naive re-tagging on already examined devtest outcomes is not an independent confirmation. Decide the discovery/evaluation split, use the same scoring definition on comparable pre/post observations, and record what has already been seen before launching a new measurement.

This does not require a new corpus or claim unseen confirmation. Language association is the target: causal function, specific semantic properties, independently trained SAEs and the broader confidence/reconstruction investigation under Q15 remain separate.

### Measurements and the question each answers

For condition b, language l and feature f, collect content-token totals N, positive-activation counts C and activation sums A from that condition's own activations. Define `r[b,l,f] = C[b,l,f] / N[b,l]` and `mu[b,l,f] = A[b,l,f] / N[b,l]`, including zero activations. Firing means `z > 0`, matching the current tagging statistic; the historical feature-level firing-rate cutoff of 0.001 is not a token-activation threshold.

Let `l0[f]` be the fixed dev peak language. Compute the following separately for firing-rate and mean-activation profiles where applicable:

| Quantity | Definition and interpretation |
|---|---|
| Target and off-target responses | Response at l0, maximum over the other 26 languages, and their absolute FP-to-quantized changes. Detect amplitude changes and new off-target responses. |
| Peak set and target margin | All languages tied for maximum response, plus `response[l0] - max(response[others])`. Distinguish retained preference, ambiguity and a language switch without arbitrary tie-breaking. |
| Original-language share | `p[l0]`, where `p[l] = response[l] / sum(response)`. Target-anchored selectivity is `27 * p[l0]`; global S remains `max(r) / mean(r)` for comparison. Global S alone misses a switch to another language. |
| Full-profile change | Total variation `0.5 * sum_l abs(p_quant[l] - p_FP[l])`. Zero indicates identical normalized profiles; it does not establish unchanged magnitude. An all-zero profile is undefined for this comparison, not perfectly preserved. |
| Mean-based specificity | Preserve the current Deng nu definition `mu[l] - mean(mu[other languages])` for every language, especially l0. It measures a different property from firing-based S. |

Always display absolute responses alongside normalized shares: common scaling can leave shares unchanged while amplitudes deteriorate. A retained peak with declining target share/margin is reported as a retained preference with weakening specificity, rather than silently counted as unchanged. Broadening is described through these continuous changes; no new hard threshold for “same association” or semantic survival is invented.

### Baseline reproducibility, support and denominators

First report whether the FP evaluation reproduces the dev-selected label: l0 must be the unique FP firing-rate peak, have at least 50 positive content-token activations, and panel-average firing must be at least `1e-5` for an established baseline association. These support values reuse existing tagging defaults; they are operational safeguards, not proof of semantic validity. Tied, different-peak and under-supported FP cases receive explicit baseline-status flags and remain in all tables.

For each quantized condition, record independently: inactive everywhere; low support (panel-average rate below `1e-5` or fewer than 50 positive activations at the current peak); or supported with retained unique original peak, a different unique peak, or an ambiguous peak set. Retain counts at l0 as an additional flag even when a supported peak has moved elsewhere. Mean-based peaks and support counts are displayed alongside the primary firing-based labels, not used to redefine cohort membership.

The headline **association-retention fraction** is the number of original selective features with an established FP evaluation association and a supported, unique original-language firing peak after quantization, divided by the entire original selective cohort. Report the FP baseline-establishment fraction next to it so ordinary discovery-to-evaluation instability is visible. Also show the conditional fraction among features with established FP associations with its denominator explicitly stated. Neither fraction is called unchanged specificity, semantic survival or causal preservation. Report each post-status by baseline status so inactive and unstable cases cannot disappear through filtering.

Give pooled feature-weighted and macro-language summaries, along with all 27 per-original-language rows. A language with no selected features has denominator zero and an NA proportion, not zero survival. Keep controls in their own descriptive table. Do not rerun the old tier tests or open a new hypothesis-test family merely to complete this measurement check.

### Uncertainty, controls and data requirements

Save per-sentence counts, activation sums and selected-token totals for the fixed cohort, with original aligned sentence IDs. Use a paired cluster bootstrap: draw 1,012 devtest sentence IDs with replacement and apply the same multiplicities across all 27 translations, FP and quantized conditions. Recompute token-weighted profiles, support, baseline/post statuses and aggregate changes per draw; keep dev-selected feature IDs/labels and token-selection masks fixed. Proposed default: 1,000 draws, seed 0, pointwise 95% percentile intervals on aggregate fractions and median profile/margin/share changes. These quantify sentence-sampling uncertainty conditional on this corpus, selected positions and frozen cohort; they do not quantify new-corpus, SAE-training or simultaneous feature-wise uncertainty. No token-independent bootstrap, data-derived significance cutoff or equivalence claim from nonsignificance.

First inventory local/cache/known remote artifacts. The inspected legacy schema saves FP response profiles and all-language correlations, but lacks quantized response profiles and per-sentence summaries; its rung firing/magnitude statistics are reference-side arrays. If no sufficient artifacts exist, collect new sidecars without changing historical fields or outputs. Include corpus/token/cohort/configuration hashes and model/SAE provenance. Save aggregate profiles for all features and sparse sentence shards for the frozen cohort, checking that their totals agree and every condition has the same input masks.

Verify the new collector against direct small-tensor calculations, deliberate broadening/switch/inactivity examples and collection-disabled legacy outputs. Restore-only INT0 should reproduce FP; investigate departures rather than interpreting them as quantization. INT16/12 characterize the numerical floor and are not assumed to preserve every association. All-language completeness, zero/tied profiles, missing shards, language order and fixed denominators require explicit tests.
